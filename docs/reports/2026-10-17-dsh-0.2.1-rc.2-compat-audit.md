# DSH 0.2.1-rc.2 适配性审计（quota-watch ↔ 上游源码对比）

- 日期：2026-10-17
- 对比基线：本机在装 `@deepseek-ai/dsh@0.2.0-rc.2`（latest 通道）vs npm `next` 通道 `@deepseek-ai/dsh@0.2.1-rc.2`（2026-10-17 发布）
- 插件版本：`@iasiv5/dsh-quota-watch@0.1.30`（工作树）
- 方法：对插件触碰到的每一个宿主/客户端契约面，取两版 npm 包做逐字节/逐语义 diff；npm 包不分的宿主壳层（webServer 提供方、remoteWebUiPairing）单列说明
- 取证产物：`~/.dsh/` 外的本地工作区 `.dsh-research/dsh-0.2.1-rc.2-audit/`（tarball 与 diff 文件，gitignored 区，不入库）

## 结论

**无需任何代码修改即可兼容 DSH 0.2.1-rc.2。** 插件触碰的全部契约面（宿主插件 API、settings、credentials、slots、客户端 runner、插件加载器）在 0.2.1-rc.2 中要么逐字节不变，要么只做纯新增。有一项**上游行为变更**（凭据解析优先级翻转）会改变「环境变量与托管存储同时存在时用哪把 key」的答案，插件代码无需跟随，但建议在宿主升级后知晓并观察一次。

## 上游行为变更：凭据解析优先级翻转（0.2.1-rc.2 起）

`dsh-credentials-local` 的分层顺序从：

```
0.2.0-rc.2：继承环境变量（赢） > $DSH_HOME/.credentials.yaml > cwd/.env > $DSH_HOME/.env
0.2.1-rc.2：$DSH_HOME/.credentials.yaml（赢） > 继承环境变量 > cwd/.env > $DSH_HOME/.env
```

上游理由：用户在产品里显式保存的凭据应当稳定生效，启动环境（含 CI secret）只在托管存储没有该引用的值时兜底（见上游架构笔记 `2026-10-09-stored-credential-precedence.md`）。

对插件的影响：

- GLM 侧 `apiKeyEnv` 引用经 `ctx.credentials.resolve()` 取值——插件永远跟随宿主口径，**无代码影响**；但若同一引用同时存在于环境变量与托管存储，宿主升级后探测会用**托管存储里的那把 key**。属预期且更符合直觉，仅需在宿主升级后看一眼 GLM 行是否正常 ready。
- 空值语义不变（「空值处处视为不存在」），插件的 missing 判定逻辑不受影响。
- 附带放宽：credentials 文档里的未知顶层键从硬拒绝改为保留但忽略（`ignoredKeys`），对插件无感。

## 无法静态验证的壳层（列明，不构成阻塞）

`webServer` 服务的**提供方**与 `remoteWebUiPairing` 配对服务属于宿主壳层（`dsh web` 启动的 GUI 进程内），不随上述 npm 包分发，无法做两版 npm 对比。风险评估：

- `plugin.d.ts`（唯一公开插件契约）逐字节一致，`webServer.register({kind:'exact',...})` 的消费方（`dsh-host-frontend-static`、`dsh-webhook-github`）在 0.2.1 的对应包亦无 API 变化信号；
- 插件的访问围栏是防御式双层：`isPairedOrLoopbackAllowed()` 在 `remoteWebUiPairing` 缺失/改名时自动降级为「loopback + 同源」——反向代理链路上 `socket.remoteAddress` 本就是 Caddy 的 loopback 地址，远程访问不受影响；
- 结论：唯一残留不确定性由**宿主升级后的一次冒烟**覆盖（清单见下）。

## 版本声明核对（package.json）

| 声明 | 0.2.1-rc.2 实况 | 判定 |
|---|---|---|
| `dsh.engines.dsh`（本审计后已升为 `>=0.2.0-rc.1`，随 v0.1.31 发布） | **宿主与安装器均不读取此字段**——启动守卫与安装 preflight 用的是同一个 `dsh-app-boot` 的 `evaluatePluginCompatibility()`，它只查 `peerDependencies` 中 `@deepseek-ai/dsh(-*)` 的 range（`semver.satisfies(..., { includePrerelease: true })`）；本插件 peer 仅 `@deepseek-ai/cordis`（不匹配 dsh 家族前缀，直接跳过）→ 守卫恒通过。该字段属纯声明，2026-10-17 owner 定策升为 `>=0.2.0-rc.1`（0.2.0-rc.1 = 守卫上线与 profile 形态固化的里程碑；0.1.x 早已无实测） | ✅ 已升下限，无强制风险 |
| `peerDependencies.cordis: ^4.0.2` | 0.2.1 使用 `~4.0.5` | ✅ 满足 |
| `dependencies['@deepseek-ai/dsh-credentials']: 0.1.7-rc.2`（精确 pin） | 随插件自带安装，与宿主解耦；宿主 0.2.1 仍经 `dsh-credentials-local` 提供 `ctx.credentials` 服务 | ✅ 不动 |
| `engines.node: >=20` | 无变化信号 | ✅ 不动 |

宿主侧的两道真实强制门（quota-watch 均天然免疫）：① npm/pnpm **装包时**的 peer 解析（严格 semver，预发布跨 tuple 排除——dsh-skins `>=0.1.1-rc.2` 排除 `0.2.0-rc.x` 即此坑，本插件无 dsh 家族 peer，不适用）；② 宿主启动/安装器守卫（`includePrerelease: true` 宽松语义，且只查 dsh 家族 peer）。

附注（与插件无直接关系，避免误判）：npm 上 `@deepseek-ai/dsh-credentials` 的 `latest` dist-tag 指向 `0.0.1-rc.1`（另一条 0.0.x 版本族），`0.2.1-rc.2` 实际存在——查新版用 `next` dist-tag 或列全版本，勿以 `latest` 为准。

## 宿主升级到 0.2.1-rc.2 后的冒烟清单

1. journal 锚点：无 `skipping profile bundle`（版本守卫放行）；
2. 胶囊出现且双 provider ready；冷启动无 ~30s 空窗（017 §7 判据仍在位）；
3. 详情面板：GLM 额度窗口/今日用量、Copilot 额度渲染正常；
4. 侧边栏卡片开关生效；bot 视图下卡片让位（`shellTakeover` 哨兵）；
5. 国内站重置卡只读查询正常（不消费）；
6. 空闲暂停日志出现（`quota-watch: idle — …`）且请求后恢复；
7. 若 GLM key 同时存在于 env 与托管存储：确认升级后用的是托管存储那把（优先级翻转的可见后果）。
