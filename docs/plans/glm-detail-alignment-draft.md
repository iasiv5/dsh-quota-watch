# GLM 详情面板下一版设计（逐题已确认）

本文件记录 /grill-with-docs 中逐轮确认的产品决定、只读核实的事实与质量门槛。Q1–Q23 均已得到用户明确答复，作为 writing-plans 的完整设计输入；本文件不是实施计划，也不代表已修改运行中的插件。

## 已确定的根决策

- **承载**：继续使用胶囊/侧栏行打开的浮动详情面板，不增设独立页面。
- **第一眼信息**：保留现有「今日 Tokens／调用次数 → 额度窗口 → 分模型用量」的顺序、顶部大数字主视觉与本轮截图区域的正常态表现；不因插件名称而强迫额度窗口上移。
- **本轮范围**：以 GLM 详情面板为中心，概览、胶囊、侧栏卡片和 Copilot 详情仅在共享交互确有必要时联动。
- **视觉约束**：继续遵从 DSH 深浅主题和原有界面体系，着重改善可读性、状态说明与操作反馈。
- **自动用卡退役**：下一版移除长期自动消费授权与宿主自动花卡，保留查卡和经用户确认的手动用卡；旧宿主授权须失效并防止回退旧版本时意外复活。设计权衡见 [ADR 0004](../adr/0004-retire-automatic-card-redemption.md)。
- **重置卡区域**：分隔线和标题始终存在；权威查询中、无可用、查询失败、查到可用卡时呈现不同内容。零卡不应使整个区域消失；详情标题栏的「立即刷新」仍是手动重查入口。

## 第二轮已确认的呈现原则

- **Q6**：有卡时只展示张数非零的卡种、最早到期日与手动操作；零张卡种不占行。
- **Q7**：本轮查卡失败时显示「额度重置卡 · 查询失败」，不把上次卡数当作当前可用，也不提供旧库存的重置按钮。
- **Q8**：手动用掉最后一张卡后，结果反馈不能被零卡状态吞掉；POST 结果未知不能静默消失或自动重试。不同结果按 Q16 的生命周期处理，结果未知按 Q18 跨页面刷新/宿主重启持续提示至用户明确核实。
- **Q9′**：正常周期缓存不加过期标记；今日用量独立查询短暂失败时沿用原数字与外观，连续无法更新超过约 5 分钟时在原数字位置显示 `—`，不增加标记、不改变两张大数字卡的正常布局，恢复后回到新值。
- **Q10′**：「立即刷新」请求中显示「刷新中」并禁用重复点击，完成后恢复；不为刷新动作额外弹成功/失败提示。「额度重置卡 · 查询失败」属于查询结果状态，手动用卡成功或结果未知属于消耗操作反馈，二者保留。
- **Q11**：在窄面板只有卡区可换行/增高以容纳卡种、到期日与按钮；不因卡区内容扩大整块面板或重排已经认可的上部统计。
- **Q12**：本轮不擅自统一时区、不改变正常态截图文案；宿主本地「今日」、浏览器本地重置时刻、按北京时区解释卡到期的差异作为已知限制记录，上游时区契约未经证实前不宣称服务商统一按北京时间计算。

## 第三轮已确认的操作原则

- **Q13**：今日两张大数字因长时间无成功数据降为 `—` 时，分模型旧数也不再冒充今日数据；用一行简短的「今日分模型数据暂不可用」代替。额度窗口不受今日用量的失败牵连。
- **Q14**：按卡种汇总张数及最早到期日，不逐张列卡、不要求用户挑卡号；手动使用前宿主实时重查并默认选择最早到期的一张。
- **Q15**：继续在卡区内二次确认，写清卡种、影响的额度窗口与不可撤销性；确认请求中禁重复点击。取消、Esc、关闭面板只撤销尚未提交的确认；已经发送的请求不能被宣称已取消。
- **Q16**：手动用卡成功短暂显示结果（约 5 秒）后回到最新库存；明确失败保留到下一次操作或刷新；结果未知持续醒目且不自动重试，并按 Q18 跨面板/页面重启留待用户核实。
- **Q17**：新版本不再有自动消费分支；首次启动将旧宿主两项 `enabled` 持久置为 false，必要时创建全关闭覆盖而不是直接删除旧设置文件，以免旧版回退后从 profile 初值重新授权。写盘失败时新版本仍无自动消费能力，但须明确记录回退风险。

## 第四轮已确认的范围与安全原则

- **Q18 已确认**：宿主持久保存结果未知的最小待核实记录（卡种、发生时刻、未知状态及用于防陈旧确认的 opaque attemptId，不含凭据或服务商卡编号）；关闭面板、刷新页面或重启后仍显示，用户核对官方卡数与额度并明确点击「我已核实」才清除。不把关闭面板当作确认。权衡见 [ADR 0005](../adr/0005-persist-unknown-manual-redemption.md)。
- **Q19 已确认**：固定重置卡区域仅适用于已验证的国内站个人版 GLM；国际站不显示区域，不把“不支持查询”伪装为“无可用”。
- **Q20 已确认**：「约 5 分钟失败状态」是一次连续失败片段的累计时长，不是每次 60 秒轮询重新计时；首次今日用量查询失败只记一次起点，后续失败沿用起点，该项查询成功才清零。没有实际失败时，单纯等待下一轮不启动计时。
- **Q21 已确认**：卡行正常态仅显示最早到期 MM/DD；悬停、键盘聚焦和辅助技术可获取完整原始到期时间，并清楚说明对无时区上游字段暂按北京时间解释，不宣称官方时区契约已验证。

Q20 已确认的状态迁移：

| 今日用量观测 | 连续故障起点 | 两张大数字／分模型 |
|---|---|---|
| 尚无任何成功数据 | 无 | `—`／暂不可用 |
| 最近查询成功，等待下一轮 | 无 | 上次成功值／分模型数据 |
| 首次失败，原先有成功数据 | 只在此时记一次 `failureSince` | 短暂沿用旧值与原外观 |
| 后续轮询仍失败 | 不重写 `failureSince` | 距首次失败约 5 分钟后一起降级 |
| 今日用量重新成功 | 清除 `failureSince` | 一起恢复新值与分模型数据 |

## writing-plans 输入审查确认的消耗安全约束

- **Q22 已确认**：手动 POST 结果未知且未核实时，禁止再次手动用卡；用户查对官方卡数和额度、点击「我已核实」，且插件成功重查后才解锁。任意时刻最多一笔待核实消费。
- **Q23 已确认**：在发出不可撤销 POST 之前持久写入进行中记录；写盘失败便拒绝 POST，绝不消耗卡。进程在 POST 前后退出时，未结清记录在下次启动按结果未知呈现；明确的成功/失败须结束该进行中记录。

## 场景验收

- 只有一种卡可用时，仅该卡种有库存行；另一种的零张占位不出现，固定分隔线与标题仍在。
- 两种卡均权威确认为零时，固定区域明确显示「无可用」；本轮查询失败则明确显示「查询失败」，不能把上次卡数作为当前可操作库存。
- 未提交的卡片确认按取消、Esc、关闭面板后必须清除，重新打开不再冒出旧确认，也不产生用卡 POST；一旦确认请求已发出，关闭面板不宣称撤销该请求。
- 用户手动使用最后一张卡后，即使库存回到零，成功反馈仍短暂可见约 5 秒；明确失败保留到下一次操作/刷新。结果未知不能自动重试或按普通计时器消失；最小待核实记录跨关闭/刷新/宿主重启保留，须明确「我已核实」才清除。
- 「立即刷新」请求进行中只允许一次操作，显示「刷新中」，完成后恢复按钮；完成时不额外弹刷新成功/失败消息，查询失败仍由固定卡区自身的「查询失败」状态表达。
- 正常周期缓存不出现过期标记；今日用量首次无有效数据时显示 `—`，有旧值且短暂失败时继续显示旧值，连续无法更新超过约 5 分钟后两张大数字显示 `—` 且分模型旧数统一替换为「今日分模型数据暂不可用」，恢复成功后一起恢复。
- 窄面板的卡区可纵向增高/换行，卡种、到期日和手动按钮不能被截断；上方已认可的今日数据、额度窗口和模型正常态不因卡区内容重排。
- 下一版宿主轮询不得再发起自动用卡 POST；首次启动将两项旧 `enabled` 持久写为 false（旧设置不存在时也覆盖 profile 初值），回退不能复活旧授权；手动用卡的卡区内二次确认、花卡前复核、请求中防重复仍在。

## 只读核实、待后续讨论的事实

- 今日用量的查询时间窗按**宿主进程本地日历日**组成；现有仓库证据不足以断言服务商把该无时区参数解释为北京时间。
- 额度窗口重置时间当前按浏览器本地时区显示；重置卡的最早到期日按北京时区显示 MM/DD；三种口径目前没有统一的界面标识。本轮确认暂维持现状，是否统一展示时区留待上游契约核实后单独讨论。
- GLM 额度探测可成功而今日用量探测单独失败；宿主会保留后者的旧数值并标记 stale，但现有详情的大数字没有独立的过期提示。
- 当前版本在自动用卡授权已开启且跨过阈值时，「立即刷新」触发的额度探测可能随后触发自动消费。只有新版本宿主逻辑退役且重启生效后，才可断言刷新只读。

## 实施时的非协商质量门槛（不等于用户已批准实施）

- 已认可的 GLM 顶部正常态需在深色/浅色、中文/英文与 Web/Desktop 面板核对；窄屏底部 sheet 及卡区按钮均不得横向截断。
- 真实按钮和确认流程须可通过键盘聚焦/触发/取消，状态文案对辅助技术可辨；任何日期提示不能只靠鼠标悬停取得。
- 自动化回归使用合成上游响应验证零卡、单卡种、查询失败、请求中、手动成功/确定失败/结果未知和旧授权退役；不能用真实卡片做自动化消费测试。
- 发布装机与宿主重启是不同阶段：新包落盘但旧进程仍在运行时，不能宣称自动用卡已退役；现场验证只在明确同意重启后进行。
